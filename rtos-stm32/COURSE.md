# STM32 + FreeRTOS 系统课程大纲 v1.0

**课程定位：** 面向具有单片机基础的嵌入式软件工程师，从 Cortex-M 架构开始，逐步掌握 FreeRTOS 内核、应用开发、STM32 外设集成和实时系统工程实践。

**学习方式：** 教材阅读 + 原理讲解 + 源码分析 + 实验 + 调试 + 阶段考核。

**建议周期：** 不设硬性完成期限。每章分为若干次课程，每次约 45～60 分钟，完成实验和考核后再进入下一章。

---

## 一、课程目标

完成课程后，应具备以下能力：

1. 理解 ARM Cortex-M 的处理器架构、异常、中断和上下文切换机制。
2. 理解 RTOS 调度器、任务状态、优先级、任务栈和系统时钟的实现原理。
3. 熟练使用 FreeRTOS 的任务管理、队列、信号量、互斥量、事件组、任务通知和软件定时器。
4. 理解 FreeRTOS 与 Cortex-M 的硬件交互，能够分析 SVC、PendSV、SysTick 的执行过程。
5. 掌握 STM32CubeMX、HAL、GCC、CMake、GDB 的现代开发工作流。
6. 能够设计多任务嵌入式应用，处理任务同步、资源竞争、中断通信、内存管理和实时性问题。
7. 能够使用 GDB、断点、寄存器、内存观察和运行时统计定位常见 RTOS 故障。

## 二、开发环境与实验平台

### 当前环境

- Windows 11
- VSCode + Remote WSL
- WSL2 Ubuntu 22.04
- GCC、Arm GNU Toolchain
- CMake + GNU Make
- GDB / GDB-Multiarch
- QEMU System ARM
- STM32CubeMX（图形化配置）

不使用 Keil 作为课程的主要开发环境。

### 三种实验环境

**A. FreeRTOS POSIX**

在 Linux 上运行 FreeRTOS 移植版本，主要验证 API、任务间通信和应用程序逻辑。

限制：不能模拟真实 Cortex-M 异常、中断优先级和硬实时行为。

**B. QEMU Cortex-M3**

使用 QEMU MPS2 AN385 模型，模拟 Cortex-M3 处理器，主要研究异常、中断、任务栈、上下文切换和底层移植。

限制：它不是 STM32，不能代替真实 STM32 外设实验。

**C. STM32CubeMX + GCC**

生成真实 STM32 目标工程，进行代码生成、编译、链接和工程分析。没有开发板时以编译和静态分析为主。

以后获得开发板，再补充真实烧录、SWD 调试、DMA、外设时序和低功耗实验。

## 五、每章课程的教学标准

每章不是简单给出一份知识点列表，而是按照以下结构生成完整教学内容：

1. **课程导读**：说明本章在整个知识体系中的位置、学习目标和先修知识。
2. **知识讲解**：从基本概念开始，系统解释原理、工作机制、设计原因和实际应用。
3. **原理图解**：根据需要绘制数据流、任务状态图、异常流程图、内存布局图和时序图。
4. **教材阅读**：指定资料库 PDF 中的具体章节和小节，区分必读和选读。
5. **源码分析**：结合 FreeRTOS 官方源码和 Cortex-M 移植层，分析关键函数及调用关系。
6. **实验设计**：给出实验目标、工程结构、完整代码、编译命令、运行方式和预期现象。
7. **调试分析**：使用 GDB/QEMU 观察寄存器、内存、任务栈和程序执行流程。
8. **课后练习**：包含概念题、代码分析题和设计题。
9. **章节考核**：通过小测和实验验收，确认是否真正掌握。

课程内容应当采用教材式讲解，保持完整的逻辑和足够的技术深度，不要把一个概念拆成大量互不关联的短句。

## 六、学习进度与考核

每章设置四个掌握等级：

- L1：能够解释基本概念。
- L2：能够阅读和理解相关源码。
- L3：能够独立完成实验和调试。
- L4：能够应用到实际工程并分析设计取舍。

进入下一章前，原则上应达到 L3。复杂章节允许分多次学习，不要求一次完成。

每章结束后生成一份学习记录，包含：

- 已掌握的知识。
- 已完成的实验。
- 尚未解决的问题。
- 需要复习的概念。
- 下一章的先修要求。

课程进度以实际掌握情况为准，不以日历时间为准。

## 七、课程最终原则

1. 优先使用 C 语言学习 FreeRTOS 内核，不急于引入 C++ 封装。
2. 优先使用 VSCode、GCC、CMake、GDB 和 QEMU。
3. 不依赖 Keil，不要求购买开发板才能开始。
4. 不把 POSIX 模拟等同于真实 Cortex-M 实时行为。
5. 不把 QEMU 的通用 Cortex-M3 平台等同于 STM32。
6. 不为了展示代码而过度设计实验工程。
7. 理论、源码和实际执行结果必须相互验证。
8. 对不同 FreeRTOS 版本、编译器和 Cortex-M 内核的差异进行明确说明。
9. 不确定的 API 行为、寄存器含义和硬件特性，应查阅官方资料，不凭经验猜测。

知识点组织与章节边界

1. 每个知识点必须有一个明确的主要归属章节，在该章节集中完成定义、原理、设计原因、源码分析、实验和考核。
2. 前置章节允许为了实验需要提前使用后续知识，但只介绍完成当前实验所必需的内容，不提前展开系统教学。
3. 后续章节遇到已学知识时，优先引用原章节，不重复讲解基础内容。
4. 如果后续章节需要从不同层次深入同一知识点，应明确说明新增的研究角度，避免重复教学。
5. 每章结束时整理该章的核心知识笔记，保证相关概念能够集中查阅，而不是散落在不同课程记录中。
